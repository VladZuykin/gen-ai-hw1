# Отчёт по финальному проекту

## 1. Задача и данные

**Задача:** Разработка системы для поиска фильмов по описанию сюжета.

**Зачем:** Пользователь помнит сюжет, ключевые детали или персонажей, но не помнит название фильма. Система должна находить фильм по текстовому описанию, используя комбинацию RAG-поиска по датасету сюжетов и веб-поиска для подтверждения.

**Данные:**
- **Источник:** Kaggle — Movie Plots from Wikipedia in Russian (maksimpotorochin/movie-plots-from-wikipedia-in-russian)
- **Объём:** 45 812 фильмов (проиндексировано 3 000 для демонстрации)
- **Колонки:** title, year, plot, summary, genre, imdb_rating
- **Подготовка:** автоматическое скачивание через kagglehub, очистка данных, рекурсивный чанкинг (chunk_size=512, overlap=80), индексация в RAG с сохранением кэша

---

## 2. Система

**Архитектура:** Мультиагентная система на основе паттерна Планировщик-Исполнитель-Критик.

```
Запрос пользователя
    ↓
Планировщик (planner.py)
    → оценивает сложность запроса
    → выбирает количество чанков из RAG (3-20)
    → решает, нужен ли веб-поиск
    → перефразирует запрос для веб-поиска
    ↓
Исполнитель (executor.py + orchestrator.py)
    → поиск в RAG (BM25 + Dense + RRF)
    → веб-поиск через DuckDuckGo (если включён)
    → загрузка полного текста страниц (при низкой уверенности)
    → генерация ответа LLM
    ↓
Критик (critic.py)
    → проверяет уверенность (0-1)
    → считает галлюцинации (hallucination_count)
    → принимает решение: accept / increase_rag / rephrase_web
    ↓
Если ответ принят → финальный ответ
Если нет → повтор с дополнительным контекстом (до 3 попыток)
```

**Использованные техники курса (6 шт.):**

| # | Техника | Реализация |
|---|---------|------------|
| 1 | **RAG** | Гибридный поиск: BM25 (ключевые слова) + Dense (эмбеддинги) + RRF (ранжирование). `rag.py` |
| 2 | **Мультиагент** | Планировщик → Исполнитель → Критик. `planner.py`, `orchestrator.py`, `critic.py` |
| 3 | **LLM-as-Judge** | Критик проверяет ответы, считает галлюцинации (я его совместил с критиком). `critic.py` |
| 4 | **Агент с инструментами** | `search_rag` и `search_web` — два инструмента, которые агент вызывает. `tools.py` |

**field_validator:**
```python
@field_validator('year')
@classmethod
def validate_movie_year(cls, v: int) -> int:
    if v < 1888:
        raise ValueError(f'Год {v} слишком ранний для фильма')
    if v > datetime.now().year:
        raise ValueError(f'Год {v} не может быть в будущем')
    return v
```
Проверяет, что год выпуска фильма находится в диапазоне 1888–текущий год.

## 4. Где пайплайн ошибался

### Пример 1: Тесты №2 и №4 — "Ведьма: Возрождение" vs "Ведьмовство"


RAG нашёл несколько итальянских фильмов ужасов про ведьм, но с очень низкими scores (~0.027). Веб-поиск через DuckDuckGo вернул страницу "Ведьмовство (1988)" на Википедии. LLM выбрала этот фильм, потому что он соответствовал ключевым словам (Италия, ужасы, ведьма).

**Почему ошиблась:**
- "Ведьма: Возрождение" отсутствовала в проиндексированных 3000 фильмах
- Веб-поиск выдал более старый, но похожий фильм

Критик принял ответ с уверенностью 0.80, не заметив ошибки.
С прямым описанием из кинопоиска уже нашлось, уверенность тоже проставилась 0.8. Логично, что часто будут такие проблемы, когда ищешь непопулярный фильм с популярной концепцией. Это можно исправить тем, что будет выбираться не один, а несколько подходящих под описание фильмов. Но все равно будут проблемы с поисковиком, если модель не выделит правильные ключевые слова (а она не сможет это сделать при недостаточно подробном описании пользователем).  


### Пример 2: Тест №6 — "Люди в чёрном" не найдены

**Вход:** "Двое парней в строгих костюмах и тёмных очках ловят инопланетян, которые маскируются под людей"

**Ожидалось:** Люди в чёрном (1997)

**Получено:** Неизвестно (1900)

**Что произошло:**
RAG не нашёл релевантных результатов (все scores ~0.02). DuckDuckGo вернул 3 результата, но все нерелевантные: "Инопланетянин" (1982), Яндекс Кью, Кинопоиск. Ни один не содержал информации о "Людях в чёрном". В трейсе видно, что веб-поиск вернул страницы про другие фильмы с инопланетянами, но не про конкретный запрос. В результате система честно ответила "Неизвестно" с уверенностью 0.00.

**Почему:**
- "Люди в чёрном" отсутствуют в проиндексированных 3000 фильмах
- DuckDuckGo действительно не выдает по подобным запросам людей в черном.

Как это можно решить? Парсить с Google, он тут просто лучше ищет. Или иметь проиндексированный сюжет для такого популярного фильма.


### Пример 3: Тест №11 — "Титаник" vs "Непотопляемый"

**Вход:** "Корабль, который считали непотопляемым, но он всё равно утонул, а влюблённые едва успевают попрощаться"

**Ожидалось:** Титаник (1997)

**Получено:** Непотопляемый (2024)

**Что произошло:**
RAG не нашёл "Титаник" в 3000 фильмах. Веб-поиск через DuckDuckGo вернул страницу про датский фильм "Непотопляемый" (2024) — фильм про расследование крушения Титаника.

**Почему:**
- "Титаник" отсутствует в проиндексированных 3000 фильмах
- Веб-поиск выдал фильм-расследование про Титаник, а не сам "Титаник"
- LLM не смогла отличить фильм про катастрофу от фильма-расследования
- Ключевая деталь "влюблённые прощаются" была проигнорирована

**Искажение:** Система выдала похожий по теме, но совершенно другой фильм. Уверенность 0.60.

В целом логично при условии, что модель и критик опирается на данные, а не свое знание. А данные были именно с этим фильмом. Если бы задача была в поиске топ-n результатов, то можно было бы просить у модели добавлять те фильмы, про которые она уже априори знает. Тут снова проблема в DuckDuckGo и отсутствии искомого фильма в RAG.


### Тест №9: верно, но данными не подтверждено

Критик проставил галлюцинацию и "confidence": 0.3 и отклонил ответ, потому что данными не подтвердилось, потому что веб-поиск и RAG дал другое. Тут снова проблема с DuckDuckGo и неполной базой.


## 5. Выводы

**Что бы я оставил в проде:**
1. **RAG** — действительно находит похожие сюжеты, когда фильм есть в датасете (тесты 13, 14). В 13-м тесте нужный фильм попал в RAG, скор был 0.98, что логично, в 14-м попала другая часть.
2. **Критик + Судья** — неплохо оценивает уверенность по данным, фиксирует галлюцинации. Когда фильм не найден (тест №6, №9), критик не галлюцинирует

**Что можно улучшить:**
1. **Полная индексация** — проиндексировать все 45 812 фильмов (тогда "Матрица", "Титаник", "Люди в чёрном" будут найдены)
2. **Веб-поиск** — хотя бы заменить DuckDuckGo HTML-парсинг на Google Custom Search API 
3. **Перефразирование запросов** — генерировать короткие запросы с ключевыми словами вместо длинных 

Сама система неплохая, можно увеличить векторную БД, попарсить для нее еще непопулярных фильмов и сделать поиск получше.
