## 1. Новый инструмент `compare_periods`

### Сигнатура

```python
def compare_periods(
    metric: str,
    period_a: str,
    period_b: str,
) -> dict:
```

Возвращает:
```python
{
  "metric": ...,
  "a": {"date": ..., "value": ...},
  "b": {"date": ..., "value": ...},
  "delta": ...,
  "ratio": ...,
  "source": ...

```

### Примеры из последнего прогона

**1. Рост USD с января 2022 по апрель 2026**

```text

-> {"a": {"date": "2022-01-01", "value": 74.2926}, "b": {"date": "2026-04-01", "value": 81.2504}, "delta": 6.9578, "ratio": 1.093654}
```

**2. Изменение инфляции с марта 2024 по март 2025**

```text

-> {"a": {"date": "2024-03", "value": 7.72}, "b": {"date": "2025-03", "value": 10.34}, "delta": 2.62, "ratio": 1.339378}
```

**3. Неоднозначный формат даты**

## 3. Диагностика ошибок

### Ошибка 1 — лишние шаги на свежих данных

```text
[step 1] call: get_key_rate
[step 1] call: get_inflation, args: {"year": 2026, "month": 5}, obs: {"error": "нет данных ИПЦ на 2026-05"}
[step 2] call: get_inflation, args: {"year": 2026, "month": 4}, obs: {"error": "нет данных ИПЦ на 2026-04"}
[step 3] call: get_inflation, args: {"year": 2026, "month": 3}, obs: {"year": 2026, "month": 3, "cpi_yoy": 6.8, "source": "rosstat_csv"}
```


**Причина:** данные отсутствуют за нужный день.

**Что бы я исправил:** Добавить инструменты, которые вовращают диапазон значений, которые есть. Сделать вызов нескольких инструментов одновременно. Указать модели, что стоит запрашивать данные за интервал, который пользователь попросил, и узнавала допустимые интервалы, чтобы не делать за несколько шагов.

### Ошибка 2 — битый формат периода

```text
[step 1] call: compare_periods, args: {"metric": "fx_USD", "period_a": "2022-01", "period_b": "2026-04"}
[step 1] obs: {"error": "Ошибка получения данных для периода A (2022-01): Для курса валют нужен формат YYYY-MM-DD, получено: 2022-01"}
[step 2] call: compare_periods, args: {"metric": "fx_USD", "period_a": "2022-01-01", "period_b": "2026-04-01"}
```

**Тип ошибки:** битый формат аргументов.

**Причина:** в промпте не описано явно, как применять `compare_periods`: какой формат даты для какой метрики.

**Что бы я исправил:** в промпт добавить блок применения инструмента:

- Для `fx_USD`, `fx_EUR`, `fx_CNY`, `key_rate`: `period_a` и `period_b` — `YYYY-MM-DD`.
- Для `cpi`, `unemployment`: `YYYY-MM`.
- Как реагировать, когда формат другой. Если данные по дням, а просят за месяц, то стоит уточнить, какую именно статистику пользователь хочет посчитать. Если шагов потребуется больше, чем мы допускаем, или из данных такое не получить, явно выводим пользователю.

Также можно добавить примеры верных и неверных вызовов:

Верно:
```text
compare_periods(metric='fx_USD', period_a='2022-01-01', period_b='2026-04-01')
compare_periods(metric='cpi', period_a='2024-03', period_b='2025-03')
```

Неверно:
```text
compare_periods(metric='fx_USD', period_a='2022-01', period_b='2026-04')  # нужен YYYY-MM-DD
```

### Ошибка 3 — лишний пересчёт результата инструмента

```text
[step 1] call: compare_periods, args: {"metric": "fx_USD", "period_a": "2022-01-01", "period_b": "2026-04-01"}, obs: {"ratio": 1.093654}
[step 2] call: calculate, args: {"expression": "81.2504 / 74.2926"}, obs: {"result": 1.093654}
[step 3] final: "Курс доллара США вырос ... в 1,094 раза"
```

**Тип ошибки:** лишний вызов инструмента.

**Причина:** агент пересчитывает `ratio` вручную, хотя он уже есть в ответе `compare_periods`. В промпте не указано, что `delta` и `ratio` не нужно пересчитывать.

**Что бы я исправил:** в промпт добавить правило: 

- «реагируй минимальным количеством действий; если инструмент уже дал результат — не делай лишних вычислений»
- если не сработало, то явно бы указал «Если `compare_periods` уже вернул `delta` и `ratio` — не пересчитывай их через `calculate`» или добавил бы пример.

Самый хрупкий элемент — промпт. В нем не указывается:
